# 小批量文档验收与返工卡

本卡为原创验收模板，所有执行栏默认为未运行。下载的编号清单是模板，所列DOCX尚未生成。请在自己的练习副本中填写；不把本卡签成本站已经测试成功。

## 开始前

- 真实执行电脑：待填。
- Harness版本/平台：待填。
- 当前模型与额度入口已查看：待填。
- 工作区绝对路径：待填。
- 输入文件：待填。
- 本次输出目录：待填。
- 当前实际可见的文档技能：待填。
- 未准备好的环境/权限：待填。

官方入口为 [DeepSeek Harness](https://www.deepseek.com/en/harness/)。Desktop与CLI/Web是两条路线。桌面包内置环境的说明不能替代CLI/Web的实际依赖核对。[Office技能说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/skill/skill-office/README.zh.md)明确：结构检查不证明外观、特性保留或公式结果正确。

## 第一次只检查 H01

1. 源编号和实际文件名是否对应？
2. 文件确实是DOCX，并能在自己的Word/WPS打开吗？
3. 六节是否齐全，目标是否可观察？
4. 时间是否等于3+5+8+4=20分钟？
5. 句子是否正确、只用了给定词汇？
6. 是否实际改过一句文字，并另存编辑测试副本？
7. 分页、字号、截断和空白页是否已人工看过？

逐项写：通过 / 未通过 / 未运行，以及证据或问题位置。一个“文件已生成”的聊天消息不能替代以上记录。

## H02 与 H03

H02：时间4+6+10+5=25；I borrow对应I借入，you lend对应you借出；教师解释与学生题目清晰可辨。

H03：时间5+15+15+10=45；8人均有介绍或下一步成果；日期与房间仍写待确认。若AI补造场地或日期，把原输入对应位置写进问题栏。

每份都重新做打开、编辑、外观与内容检查。H01通过不代表其余两份通过。

## 对账和返工

- 约定交付物：3份DOCX、1份manifest.csv、1份验收说明.md。
- 各行清单能否定位到对应真实文件：待填。
- 输入原件是否保留：待填。
- 已运行检查与未运行检查是否分别记录：待填。
- 需要返工的编号：待填。
- 第一处问题及原因：待填。
- 修改后版本与实际路径：待填。
- 重做后复查结果：待填。

只返工未通过编号。依赖缺失、路径错误和内容错误分开记录；不要用盲目重跑整个批次解决所有问题。

## 下一份材料复用什么

可以复用六节模板、命名规则与验收过程。学生背景、时长、目标、题目答案、分享范围和未知项需要重新判断。请写一句自己的决定，以及一项仍未确定的条件。
