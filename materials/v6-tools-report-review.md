# 日报审核与按钮流程：原创设计卡

本卡使用虚构记录。本站没有登录飞书，没有建立流程或消息发送。所有运行、权限和送达栏均为待本人核对。可以先在本地完成筛选、草稿和纸上走查，再决定是否在自己的测试环境实测。

## 固定日期和筛选结果

练习日期：2026-10-09；时区：Asia/Shanghai。条件必须同时满足：日期等于练习日期，分享范围等于可分享测试组。

纳入D01、D02、D03、D04、D07，共5条。排除D05：旧日期；D06：仅自己可见；D08：未来日期。当前日期与本练习固定日期不同，也不能擅自更改原记录。

若无有效记录，停止生成对外日报；不要把昨天记录拿来补齐。条件与无结果处理可参考 [飞书查找记录](https://www.feishu.cn/hc/zh-CN/articles/239533363334)。本课新手路线先用表格筛选和人工复制，不要求配置原生AI节点。

## 两张表的职责

工作记录表：编号、日期、时区、分享范围、状态、事实、证据、下一步。记录者负责真实填写与范围判断。

日报审核表：每份日报一行，建议字段为日报ID、日期、来源编号、草稿版本、审核后文本、审核人、审核状态、目标测试群、发送状态、发送证据、按钮。

日报ID、审核状态、发送状态等是本课设计的自定义文本/选择字段。它们用于追踪，不是飞书自动给你提供的幂等键、审批锁或原子事务。

## 人工审核卡

- 日期和时区一致：待填。
- 来源编号恰有5条：待填。
- 私有、旧日期和未来记录已排除：待填。
- 完成/进行中/受阻/计划没有混淆：待填。
- 10张、2/3页、30秒等数字与原行一致：待填。
- 文件本机检查没有误写为发布或课堂成功：待填。
- 实际接收方和授权范围：待填。
- 当前发送身份及其权限条件：待填。
- 已审核的文本版本、审核人和时间：本人填。
- 尚未确定事项：待填。

人工实际读稿后才填写已审核。内容改变需重新审核，不能沿用旧版本的确认。

## 按钮触发设计

当前 [按钮触发教程](https://www.feishu.cn/hc/zh-CN/articles/804644015036)采用两段配置：先在流程选择“点击按钮时”的按钮类型与范围，再在按钮字段或组件里关联流程。不要照旧图猜成在触发器里只选择一个固定按钮。

本设计使用日报审核表中的按钮字段，因为它与所在行关联，可引用这行审核后的文本。仪表盘按钮组件与行数据关系不同，不应直接替换。

纸上设计链路：本人核对一行审核状态、版本与接收方→点击该行按钮→按当前类型/记录范围匹配流程→发送核准文本到明确测试接收方→本人查看真实消息和流程日志→回填发送证据。

若本人的界面可以在流程范围或条件判断中表达“已审核且未发送”，配置后仍需用反例验证。若没有对应入口，保留明确的手工发送前检查；不能编造按钮或触发器。多个用户同时点击和状态修改的先后顺序需要另行验证，本卡不保证只发送一次。

## 发送身份和接收方核对

按 [飞书发送消息说明](https://www.feishu.cn/hc/zh-CN/articles/986962389649)核对选择的身份。多维表格应用机器人、配置者本人、多维表格助手和自定义群机器人的条件不同，不能混用。

若用多维表格应用机器人，本课以企业内测试群为例，需核对最后启用流程的人在群中，以及机器人会取得当前表格编辑权限这一影响。使用其它身份时回原文查对应条件。不要在课程中填真实群webhook或账号凭据。

将来获授权实测前，填写唯一明确接收方、消息标题、核准文本版本、发送身份、配置权限和停用方法；不能泛写“发到工作群”。这次离线练习不启用真实流程、不点真实发送。

## 四种情形的走查

1. 未审核：停止，保留草稿；不能发送后再补审批。
2. 正常：只使用指定已审核行的版本；将来实测后检查实际接收方、标题、编号和数字。
3. 零条有效记录：停止，记录原因；不能补造当日工作。
4. 状态未知：先看流程日志与群内真实消息；没有确认前不连点重发。

异常处理、停止条件和这四种测试情形是课程设计，不能作为飞书原生已经实现的证明。未来真实发送后，只有观察到送达并核对内容才能写“已发送”；失败、未知与未运行分别记录。
